# その手法が「本物か」確かめるのに何か月かかるか

Qiita の記事「【バックテストする人向け】その手法が「本物か」確かめるのに何か月かかるか、Pythonで計算するやり方」から来た方へ。
この記事で使ったコードの実物がこのリポジトリにあります。

## 何の話か

バックテストで良い成績が出た手法を実際に動かすとき、**何件・何か月待てば判断できるか**は、
待ち始める前に計算できます。

```
必要な件数   n = ((1.645 + 0.8416) / s)²        片側5%・検出力80%
             s = 1件あたりの「平均 ÷ 標準偏差」（コスト後）
必要な月数   月数 ≈ 74 ÷ (年率シャープ)²
24か月で確かめたいなら、コスト後の年率シャープ 1.76 が要る
```

## 🔴 よくある間違い

`n = (1.645 / s)²` は、**t の期待値がちょうど有意の線に乗る**件数です。
実際の t はその周りでばらつくので、線を越えるのは**約半分**。

**本物の優位があっても、半分は「確かめられなかった」になります。**
検出力 80% が要るなら `(1.645 + 0.8416)` を使ってください。私はここを間違えていました。

## もう1つ: 回数を増やしても時間は縮まない

売買が独立なら、必要な月数は **年率シャープだけ**で決まります。
1件あたりの優位が小さい高頻度の手法は、回数が多くても年率シャープが同じなら、
確かめるのにかかる時間は変わりません。

## このリポジトリの該当ファイル

```
src/confirm_time.py       本体。標準ライブラリだけ・依存なし
                            n_required        : 必要な件数
                            months_required   : 必要な月数
                            annual_sharpe     : 1件あたりの s → 年率シャープ
                            months_from_sharpe: 年率シャープ → 月数
                            sharpe_needed     : 月数 → 必要な年率シャープ
                            simulated_power   : 模擬で検出力を確かめる
src/test_confirm_time.py  テスト5件。式・回数では縮まないこと・24か月=1.76・
                            検出力80%・(1.645/s)² だと約50% を検査する
```

実行:

```bash
cd src && python3 -m pytest test_confirm_time.py -q
```

## このリポジトリ全体について

このリポジトリは「自分の口座で実際にいくらコストがかかっているかを測ってから、
落ちることが許されているバックテストを回す」ための道具をまとめたものです。

```
src/measure_cost.py     自分の MT5 口座の実測コスト
src/bidbar_cost.py      bid の足から実際の損益へ直す
src/backtest_engine.py  判定を回すエンジン
src/prereg_lock.py      事前宣言を sha256 で固定する
src/gate_power.py       その件数で判定して大丈夫か
src/confirm_time.py     ← この記事のコード
src/watchdog.py         常駐プロセスの無応答を検知する
```
