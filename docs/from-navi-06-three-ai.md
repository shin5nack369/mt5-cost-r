# 「確かめる役」のAIに渡す、確かめ方の実体

投資ナビ＋ の記事「3つのAIを使い分けてEAを検証する――作る役と疑う役を、別のAIにする」から来た方へ。
記事では役割分担と順番の話を書きました。ここには、**「確かめる役」が実際に何を走らせるのか**を置いてあります。
**MIT ライセンスなので、そのまま使えます。**

## 役割を分けても、基準が動くと意味がない

記事に書いた分担（書く役・確かめる役・決める役を別のAIにする）には、前提が1つあります。
**合格ラインが途中で動かないこと。** 動くなら、何人で見ても同じ結論に寄せられます。

`prereg_lock.py` は、条件と合格ラインを書いた宣言文を sha256 で固定するだけの約60行です。

```python
from prereg_lock import lock, verify

h = lock("prereg.md")        # 始める前に固定
verify("prereg.md", h)       # 1文字でも変われば False
```

🔴 **「確かめる役」に渡すのは、結果ではなく、この固定済みの宣言とコードです。**
結果だけ渡すと、確かめる役も結果に引きずられます。

## 「確かめる役」が走らせるもの

| 確かめること | 道具 |
|---|---|
| 配線が繋がっているか（信号が本当に注文まで届くか） | [`dryrun_wiring.py`](../src/dryrun_wiring.py) |
| 合格ラインが本物を通し、偽物を落とすか | [`gate_power.py`](../src/gate_power.py) |
| 往復コストを何と数えているか | [`measure_cost.py`](../src/measure_cost.py) |
| 落ちた理由がコストなのか、そうでないのか | [`diag_gross.py`](../src/diag_gross.py) |

単体テストが通ることは、**配線が繋がっていることを意味しません。**
7項目すべて通ったのに本番が 1 バイトで落ちた話は、この repo の `dryrun_wiring.py` を書いた理由です。

## 書く役と確かめる役を分ける、いちばん安い形

AIを3つ用意できない場合でも、**宣言を固定してからコードを書く**だけで、
書いた本人が後から基準を緩める経路は塞がります。順番だけが効いています。

## 使うときの前提

`numpy` だけで動きます。数字はすべて筆者の口座・筆者の検証条件での実測で、
将来の成績を保証するものではありません。
