# bid の足でバックテストするとき、スプレッドは往復1回分

Qiita の記事「MT5のbid足でバックテストするとき、スプレッドは往復1回分 — 2回引いていたのをPythonとテストで直した」から来た方へ。
この記事で使ったコードの実物がこのリポジトリにあります。

## 何の話か

MT5 の `copy_rates_*` で取れる足の OHLC は **bid（売値）** です。ask の足はありません。

bid の足で測った損益から実際の約定に直すとき、**引くのはスプレッド1回分**です。
「入る時 + 出る時」で2回引くと、**払っていない側を1回余分に引いています**。

| | 実際の約定 | bid で測った損益との差 |
|---|---|---|
| 買い | ask で買い、bid で売る | 入る足のスプレッド |
| 売り | bid で売り、ask で買い戻す | 出る足のスプレッド |

どちらも**1回分**です。

## 4つの要点

```
1. bid の足から実際の損益へ直すとき、引くのはスプレッド1回分。
   「入口 + 出口」で2回引くのは、払っていない側を数えている
2. 厳しすぎる物差しは、良い手まで捨てる。
   基準は1回分、ストレスとして2回分も出して、両方書く
3. スワップは「払う側」だけ数える。受け取りは数えない
4. 3倍の曜日はブローカーの設定（swap_rollover3days）から取る。
   曜日の番号のずれに注意する
```

🔴 これに気づいても、**過去の判定はやり直していません。**
結果を見てから物差しを変えるのは、線を後から動かすのと同じだからです。
変えたのは次の検定から。その「線を後から動かさない」ための道具は
[`src/prereg_lock.py`](../src/prereg_lock.py) にあります。

## このリポジトリの該当ファイル

```
src/bidbar_cost.py       本体。標準ライブラリだけ・依存なし
                           Bar          : 足1本（bid の OHLC ＋ その足の spread[points]）
                           bid_pnl      : bid の値だけで測った損益
                           spread_cost  : 往復のスプレッドのコスト（＝1回分）
                           rollovers    : またいだ日付の変わり目を3倍の曜日込みで数える
                           swap_cost    : 持ち越しで「払う」分だけ（0 以上）
                           net_pnl      : コストとスワップを引いた損益
src/test_bidbar_cost.py  テスト8件。bid と ask を作って
                           「実際の約定」と一致するかまで検査する
```

実行:

```bash
cd src && python3 -m pytest test_bidbar_cost.py -q
```

## このリポジトリ全体について

このリポジトリは「自分の口座で実際にいくらコストがかかっているかを測ってから、
落ちることが許されているバックテストを回す」ための道具をまとめたものです。

```
src/measure_cost.py     自分の MT5 口座の実測コスト
src/bidbar_cost.py      ← この記事のコード
src/backtest_engine.py  判定を回すエンジン
src/prereg_lock.py      事前宣言を sha256 で固定する
src/gate_power.py       その件数で判定して大丈夫かを先に計算する
src/confirm_time.py     本物か確かめるのに何か月かかるかを計算する
src/watchdog.py         常駐プロセスの無応答を検知する
```
