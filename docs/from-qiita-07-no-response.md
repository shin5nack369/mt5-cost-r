# 常駐プロセスの「無応答」を検知する

Qiita の記事「常駐プロセスの「無応答」を検知する — タイムアウト実行・ハートビート・自己診断」から来た方へ。
この記事で使ったコードの実物がこのリポジトリにあります。

## 何の話か

**`try/except` は「失敗」を捕まえる道具で、「返ってこない」を捕まえる道具ではありません。**

常駐プロセスが1つ、32時間止まりました。プロセスは生きていたので、死活監視は全部「正常」と報告していました。
周期処理の中で外部 SDK 越しに履歴を取りに行く関数が、**C 拡張の中で固まっていた**のが原因です。
`try/except Exception` で囲ってあっても例外は発生しません。ただ返ってきません。

## 5つの要点

```
1. 無応答を測れるのは別スレッドだけ。
   そしてタイムアウトしたスレッドは kill できないので、
   タイムアウトしたら続行せずプロセスごと落とす
2. 生存の根拠にログの最終行を使わない。
   ログは「出力に成功した」ことしか示さない。
   「1周終えた」だけを書くハートビートを別に持つ
3. 判定を OK / NG の2値にしない。
   「古い」と「見られなかった」は別物で、後者を PASS に丸めると
   一度も起動していないプロセスが正常に見える
4. 監視器自身も監視対象に入れる。
   検知器だけが古い版のまま動いていると、他を全部直しても何も通知されない
5. 検査が本物かを確かめる。
   わざと壊して、ちゃんと落ちることを見てから本番に置く
```

## このリポジトリの該当ファイル

```
src/watchdog.py         本体。標準ライブラリだけ・依存なし
                          call_with_timeout : 返ってこない呼び出しを打ち切る
                          Heartbeat         : 「1周終えた」を原子的に書き出す
                          check_heartbeats  : OK / STALE / UNKNOWN の3値で返す
                          self_report       : 監視器自身の生存を書く
src/test_watchdog.py    テスト7件。タイムアウトが実際に時間内に返ることまで検査する
```

実行:

```bash
cd src && python3 test_watchdog.py
```

## このリポジトリ全体について

このリポジトリは「自分の口座で実際にいくらコストがかかっているかを測ってから、
落ちることが許されているバックテストを回す」ための道具をまとめたものです。

```
src/measure_cost.py     自分の MT5 口座の実測コスト
src/backtest_engine.py  判定を回すエンジン
src/prereg_lock.py      事前宣言を sha256 で固定する（結果を見てから線を動かさないため）
src/gate_power.py       その件数で判定して大丈夫かを先に計算する
src/watchdog.py         ← この記事のコード
```

共通しているのは **「結果を見る前に、何なら合格かを決めておく」** という一点です。
無応答の検知も同じで、「どうなったら異常とみなすか」を先に数字で決めておかないと、
あとから「まあ動いてるし」で見逃します。
